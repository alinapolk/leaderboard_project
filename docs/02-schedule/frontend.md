# Система 2. Расписание выступлений — фронтенд

Стек и дизайн-токены те же, что в [../01-events-evaluation/frontend.md](../01-events-evaluation/frontend.md). Новый модуль: `src/features/schedule/`. Контракты и коды — [backend.md](backend.md). Образец интерфейса: `source/МодульРасписанияV5.dc.html` и `Прототип v5.dc.html` (демо: https://eop10.github.io/LeaderBoardTest/).

Предупреждающий цвет: текст `#8a5a00` на фоне `#fff4e0` (новых цветов не вводить). Мобильные экраны организатора — заглушка «Экран организатора рассчитан на компьютер» (< 1024 px). Экраны наставника и студента работают на 390 px.

## 1. Типы (предложение)

```ts
type ScheduleStatus = 'setup' | 'collecting' | 'draft' | 'published';
type ReviewStatus = 'pending' | 'accepted' | 'rejected';      // На проверке / Принята / Отклонена
type IssueCode = 'all_slots_blocked' | 'slot_shortage' | 'mentor_overlap';

interface Slot { id: number; section_id: number; starts_at: string; ends_at: string }
interface Assignment { slot_id: number; event_team_id: number; is_pinned: boolean; changed_at: string | null }
interface SectionGrid { section_id: number; break_start: string | null; break_minutes: number | null }
interface Schedule {
  status: ScheduleStatus; slot_minutes: number; changeover_minutes: number; marks_closes_at: string | null;
  seed: number; sections: SectionGrid[]; slots: Slot[]; assignments: Assignment[];
  unplaced: { event_team_id: number; reason: string }[];
  issues: { code: IssueCode; event_team_id?: number; message: string }[];
}
interface Unavailability { id: number; event_team_id: number; starts_at: string; ends_at: string;
  reason: string; /* видит организатор и автор */ review_status: ReviewStatus }
interface MarkLimit { limit: number; used: number }             // минуты
interface Admission { statuses: string[]; semester_start: string; semester_end: string }
interface PoolTeam { team_id: number; team_title: string; fits: boolean; why_not: string | null }
interface Performance { event_id: number; title: string; section: string; starts_at: string; number: number;
  changed_by_organizer: boolean; previous_starts_at: string | null }
```

## 4. Организатор: мастер расписания

Шапка: номер и название шага, бейдж статуса.

| Статус | Бейдж | Шаг |
|---|---|---|
| `setup` | Расписание не настроено | 1 «Команды и аудитории», 2 «Сетка» |
| `collecting` | Сбор отметок до {дата} / Дедлайн прошёл | 3 «Сбор отметок» |
| `draft` | Расписание построено, не опубликовано | 4 «Разбор» |
| `published` | Расписание опубликовано | 5 «Публикация» |

**Создание.** При создании предзащиты или защиты выбор «Через расписание» создаёт расписание в `setup`; кнопка «Расписание» в карточке мероприятия открывает мастер. Для мероприятия с расписанием показывается пояснение «Порядок и время выступления задаёт расписание. Аудитории назначьте на шаге «Команды и аудитории»»; перетаскивание порядка и импорт Excel недоступны.

**Шаг 1. Команды и аудитории.**
- Предзащита: правило допуска (статусы команды, начало и конец семестра), «Подтянуть команды» из витрины отделения (в списке видно, какие команды подходят и почему нет: «Статус «Заморожен» не допущен», «Начала работу вне семестра»; кнопка «Добавить N»).
- Защита: команды уже перенесены из предзащиты, правила допуска нет.
- Ручное добавление команды (форс-мажор) доступно в обоих случаях.
- Выбор аудитории для команд без неё. Организатор бронирует аудитории вне системы и вводит их сам (A29).

**Шаг 2. Сетка.** Длительность выступления, смена команд, кофебрейк каждой аудитории (начало и длительность), дедлайн отметок. Счётчик «Слотов S · команд N · запас K» по аудиториям. При нехватке: «В ауд. {X} не хватает N слотов: сократите кофебрейк или выступление». При запасе 0: «запас 0, лимит 0: наставники этой аудитории увидят сообщение, что отметить время нельзя». Максимальный лимит считает система, организатор его не вводит. Если запас в аудитории меньше двух слотов, показать предупреждение «Запас меньше двух слотов: наставники почти не смогут отметить время». Изменение сетки в `draft` сохраняет назначения, чьи слоты остались, а остальные сбрасывает: перед сохранением диалог с числом сбрасываемых назначений и подтверждением (ПР21); если из-за новой сетки у команд отметок больше лимита, показать список этих команд (отметки не удаляются, ПР6). В `published` поля неактивны.

**Шаг 3. Сбор отметок.** Кнопка «Открыть сбор отметок» (состояния «Открываем…» → «Сбор открыт»); причины блокировки: «В мероприятии нет команд», «N команд без аудитории», «в ауд. X не хватает K слотов» (со ссылкой «к шагу 2»). Список отметок по командам: интервал, причина, статус; кнопки принять / отклонить. Кнопка «Построить» (можно до дедлайна, с предупреждением «Построить» закрывает сбор: наставники больше не меняют отметки).

**Шаг 4. Разбор.** Таблица «аудитория × слот»; клик по ячейке: «Поставить сюда», «Закрепить», «Снять». Блок «Не поставлены» с причинами (например, «Свободных слотов в этой аудитории нет.»; формулировки из `issues`). Предупреждения в ячейке: «Слот занят командой …», «Наставник отметил {интервал}», конфликт наставника в другой аудитории. Блок нехватки слотов с действием «Добавить слоты» и ссылкой «Сократите кофебрейк». Команды с превышением лимита отмечены «превышен лимит». Кнопки: «Перестроить» (только по нажатию, ПР22; поле seed и кнопка «Другой seed»; расписание само не пересобирается), «Опубликовать» («Публикуем…» → «Опубликовано»). Диалог обмена: «Слот {t} занят командой «B». Она перейдёт в слот {t₂}, «A» — в {t}. Обе команды закрепятся.» После отклонения отметки в `draft`: «Отметка отклонена. Нажмите «Перестроить», чтобы она перестала мешать». Новая команда после построения: «Команда появилась после построения. Нажмите «Перестроить» или поставьте вручную.»

**Шаг 5. Публикация.** После публикации правки слотов остаются доступными: команда закрепляется, тост «Слот изменён. Команда и наставник видят новое время». Сетку менять нельзя. Кнопка «Открыть приём оценок» в карточке мероприятия становится доступной только после публикации расписания.

Состояние «Нет связи» блокирует сохранение на экранах расписания: «Нет связи. Изменения не сохранены. Проверьте интернет и повторите.»

## 5. Наставник (телефон и компьютер)

- «Расписание»: список своих команд и статус — «Сбор до {дата}», «Расписание готовится» (с подписью «Время выступления появится здесь после публикации расписания.»), «Расписание опубликовано», «Слот изменён организатором».
- Экран отметок по команде: сетка слотов аудитории плитками, поля интервала «с — по», причина, кнопка «Добавить»; список отметок со статусами «На проверке» / «Принята» / «Отклонена»; счётчик «использовано U из L минут»; «Сохранить» с индикатором несохранённых изменений. Причина видна только автору.
- Тексты и ошибки: «Укажите начало интервала», «Укажите конец интервала», «Укажите причину», подсказка «Укажите причину и нажмите «Добавить»»; «Можно отметить не больше {L} минут. Осталось {L−U}»; при L = 0 «В ауд. {X} слотов столько же, сколько команд, поэтому отметить время нельзя.»; после дедлайна «Дедлайн прошёл. Сбор отметок закрыт, расписание готовится.»; после правки «Нажмите «Сохранить»», после удаления «Отметка удалена. Не забудьте сохранить».
- После публикации: «Выступление № N, {время}»; при изменении — «Слот изменён организатором» и прежнее время.
- Форма причины: счётчик символов (3–300) и подсказка «Не указывайте медицинские и иные личные подробности — достаточно общей причины» (ПР5). Для отметок, у которых текст причины уже очищен (30 дней после мероприятия), показывать «Причина удалена».
- Вход наставника обеспечивается решением ПР1 (корпоративная почта сопоставляется с витриной); до его реализации экран проверяется только на тестовых данных.

## 6. Студент

- Член команды видит после публикации блок «Расписание вашей команды» (аудитория, время, номер) в карточке анонса и в «Мои выступления». До публикации слот не показывается.
- При изменении слота организатором — бейдж «Слот изменён организатором» (цвет предупреждения) и прежнее время.
- Просить изменить слот в системе нельзя: студент пишет организатору вне системы (A36).
- У предзащиты и защиты кнопки «Записаться» нет.

## 7. Состояния и поведение

- Загрузка, пусто, ошибка сервера, нет связи — как в системе 1 (раздел «Общие состояния экранов»).
- Кнопки с долгими действиями имеют три состояния: «Построить» → «Строим…» → «Построено».
- Тексты ошибок бэкенда `schedule_incomplete`, `slot_occupied`, `grid_locked`, `collect_closed`, `mark_limit_exceeded` показывать из `error.message`, не заменяя своими, кроме указанных выше дословных формулировок прототипа.

## 8. Что не переносить из прототипа

Демо-панель и переключатель «Сегодня в прототипе»; расписание «одновременно только у одного мероприятия» (ограничение демо); аудитории 301/303/305 и фиксированный список команд; демо-отметки (`seedMarks`); фиксированный лимит 40 минут (в продукте считает система по сетке); дедлайн «17.10.2026, 18:00» по умолчанию; прототипное построение жадным паросочетанием (см. [backend.md](backend.md), раздел 6) — логику построения реализует сервер.
