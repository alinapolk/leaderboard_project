# Система 1. Мероприятия и оценка — бэкенд

Что входит: мероприятия трёх типов (предзащита, защита, акселератор), оценочные листы, аудитории, эксперты, команды, приём оценок, итоги, создание защиты из предзащиты, анонсы, акселератор (направления, тренеры, запись студента, материалы).
Что **не** входит: расписание выступлений — система 2 ([../02-schedule/backend.md](../02-schedule/backend.md)). Общие соглашения, формат ошибок и реестр кодов — [../00-common/conventions.md](../00-common/conventions.md). Роли — [../00-common/roles.md](../00-common/roles.md).

Обозначения: ● — уже есть в бэкенде, ○ — новое.

## 1. Модель данных

```
Department 1─* events
events(predefense) 1─0..1 events(defense)     через event_evaluations.source_event_id (уникально)
events 1─0..1 event_evaluations *─1 templates 1─* criteria 1─* criterion_levels
events 1─* event_sections 1─* section_experts *─1 User
events 1─* event_teams *─1 Team               (section_id и position nullable)
event_teams 1─* evaluations *─1 User(expert);  evaluations 1─* evaluation_scores
events(accelerator) 1─* accelerator_tracks 1─* track_trainers *─1 User
accelerator_tracks 1─* track_enrollments *─1 User(student)   ○
accelerator_tracks 1─* track_materials
```

Таблицы имеют `id`, `created_at`, `updated_at`. Типы условные (PostgreSQL).

### Внешние сущности

`User`: ФИО, логин, почта, группы Django (`student`, `expert`, `organizer`, `trainer`; несколько на человека), учебная группа. `Team`: название, отделение, состав из витрины (роли «Студент» и «Наставник»), дата начала работы, статус.
Не подтверждено заказчиком (A27, A28): у `Team` нет статуса и признака «архив» в известном ответе витрины, значения статусов не определены. До уточнения действует правило допуска по ПР7 ([../decisions.md](../decisions.md)): статусы выбирает организатор, статус «Закрыт» (архив) не допускается никогда. Для сопоставления человека с витриной в `User` хранится идентификатор человека в витрине (ПР1).

### templates — оценочный лист ●

`name` (обязательно), `description`, `status` (`draft` / `locked`), критерии (`title`, `description`, `position`, уровни), `criterion_levels`: `score` (целое ≥ 0, уникален в критерии), `description`. Максимум критерия — наибольший балл среди его уровней (только чтение, в запросе не передаётся); максимум шаблона — сумма максимумов. Веса у критерия нет: вес задаётся максимумом (ПР12).
Заморозка: при публикации мероприятия шаблон → `locked`; править или удалить его нельзя (`template_locked`). Правка опубликованного листа создаёт копию в `draft` для новых мероприятий.

### events — мероприятие ●

| Поле | Тип | Правила |
|---|---|---|
| `type` | enum `predefense` / `defense` / `accelerator` | задаётся при создании, неизменяем (`event_type_immutable`) |
| `title` | text | обязательно |
| `event_date` | date | обязательно |
| `start_time`, `end_time` | time | окончание позже начала, иначе `invalid_time_range` |
| `place`, `description` | text | описание идёт в анонс |
| `publication_status` | enum `draft` / `published` | |
| `published_at` | timestamptz | |
| `registration_status` | enum `not_opened` / `open` / `closed` | ○ только `accelerator`; хранимое (ручное) значение, эффективный статус — см. раздел 2 |
| `registration_opens_at` | timestamptz, nullable | ○ только `accelerator`; автоматическое открытие записи (ПР10) |
| `department_id`, `created_by` | fk | |

### event_evaluations — оценка в мероприятии ● (только `predefense`, `defense`)

`event_id` (unique), `template_id`, `evaluation_status` (`draft` / `open` / `closed` — приём оценок; в интерфейсе «Не открыт» / «Активно» / «Завершён», код `open` остался после правки PM от 16.10, меняется только подпись), `passing_score` (только предзащита; 0…максимум шаблона), `source_event_id` (только защита; ссылка на предзащиту, уникальна). У акселератора записи нет (`not_evaluable_type`).

### event_sections, section_experts ●

`event_sections`: `event_id`, `room` (свободный текст, обязателен, уникален в мероприятии), `capacity` (○ необязательное справочное, A29). `section_experts`: `section_id`, `user_id`. Эксперт в мероприятии состоит только в **одной** аудитории (A7, `expert_already_in_event`). Назначенному добавляется группа `expert`.

### event_teams ●

| Поле | Правила |
|---|---|
| `event_id`, `team_id` | уникальная пара (`team_already_in_event`) |
| `section_id` | nullable; `null` = «без аудитории» |
| `position` | nullable; очерёдность в аудитории |
| `order_source` | `manual` / `excel` / `predefense` / `auto`. `auto` — команда добавлена по правилу допуска или поставлена алгоритмом расписания (A40, ○ значение, заменило `booking`); ручная правка меняет значение на `manual` |
| `absent` | «Неявка»; кто и когда отметил — аудит |

У мероприятия с расписанием единственный писатель `section_id` и `position` — сервис расписания (A39).

### evaluations, evaluation_scores ●

`evaluations`: одна на пару («участие команды», эксперт); `status` (`draft` / `submitted`), `comment`, `submitted_at`. `evaluation_scores`: оценка по критерию; балл должен совпадать с одним из уровней критерия.
**Итог эксперта** — сумма баллов. **Итог команды** — среднее отправленных итогов экспертов её аудитории; команды с `absent` идут отдельно, без итога (оценки хранятся). Вердикт «Прошла» — итог ≥ `passing_score`; команда с неявкой или без единой отправленной оценки не проходит (A21, не подтверждено). Если оценок меньше, чем экспертов, — предупреждение «Неполные оценки: итог по N оценкам из M»; M включает удалённых из аудитории экспертов, успевших оценить, чтобы N не превышало M (ПР11).

### Акселератор

`accelerator_tracks` ●: `event_id` (только `accelerator`, иначе `not_accelerator`), `role` (текст организатора, обязательно, уникально в мероприятии без учёта регистра и пробелов), `room` (обязательно, уникально; повтор роли или аудитории — `track_conflict`), `description`, `capacity` (○ необязательное; `null` = без лимита; ≥ 0), `position`. Все направления идут в один день (`event_date`).
`track_trainers` ●: `track_id`, `user_id`, `position`, `company`; ≥ 1 на направление для публикации; назначенному добавляется группа `trainer`.
`track_enrollments` ○: `event_id`, `track_id`, `user_id`, `created_at`; **unique (`event_id`, `user_id`)** — одно направление на студента; направление должно принадлежать тому же мероприятию (составной внешний ключ или проверка в сервисе).
`track_materials` ●: `track_id`, `title`, `file_key`, `mime` (PDF или PPTX), `size_bytes` ≤ 52 428 800 (50 МБ), `uploaded_by`.

### Анонс

Отдельной таблицы нет: анонс — опубликованное мероприятие любого типа с датой не в прошлом, видимое **всем** авторизованным пользователям. Показывать акселератор только записавшимся нельзя: запись начинается с анонса.

## 2. Статусы и переходы

Статусы независимы; на карточке показываются бейджами рядом.

**Публикация** (`publication_status`): `draft → published`, обратного перехода нет, удалить можно только черновик (`event_published` иначе).
Условия `publish` (иначе `event_not_ready`): все обязательные поля; предзащита — шаблон и проходной балл 0…максимум; защита — шаблон; акселератор — ≥ 1 направление, нет `track_conflict`, у каждого направления ≥ 1 тренер. Эффекты: шаблон → `locked`, фиксируется `passing_score`, анонс появляется у всех.

**Приём оценок** (`evaluation_status`, предзащита и защита):

```
draft ──open──▶ open ──close──▶ closed
                  ▲                │
                  └─────reopen─────┘   (кроме предзащиты, из которой создана защита — source_locked)
```

`open` — только у опубликованного мероприятия, при выполнении всех условий (иначе `event_not_ready` с `details.reasons[]`): каждая команда без неявки стоит в аудитории; в каждой аудитории есть эксперты; при расписании оно опубликовано (A40) и у каждой команды без неявки есть позиция (ПР3, причина `teams_without_position`). Эти проверки расписания подключаются через `OpenGuard` ([../00-common/conventions.md](../00-common/conventions.md)). Закрывает только организатор вручную; автозакрытия нет. В `closed` эксперт видит оценки только для чтения.

**Запись на акселератор** ○ (`registration_status`): `not_opened → open → closed`; открыть можно только у опубликованного акселератора. Организатор открывает и закрывает запись вручную. **Эффективный статус** считает сервер по времени вуза (ПР10): запись `closed`, если закрыта вручную или наступило `event_date + start_time`; `open`, если открыта вручную или задано `registration_opens_at` и оно наступило (до начала мероприятия); иначе `not_opened`; у неопубликованного мероприятия статус всегда `not_opened`. Один сервисный метод используется везде: в анонсе, при записи, смене и отмене. Состояние студента считается отдельно: `not_opened` («Запись не открыта»), `available` (может записаться), `enrolled` («Вы записаны»), `closed` («Запись закрыта»). Менять направление можно, пока запись открыта (прототип: «Сменить направление можно, пока открыта запись»).

**Защита из предзащиты:** предзащита в `closed` и без защиты → создаётся защита (`draft`, прошедшие команды, без аудиторий и позиций, `order_source = predefense`) → предзащиту больше нельзя вернуть в работу.

## 4. API

### Мероприятия и анонсы — `/api/events/`

| | Метод и путь | Права | Описание |
|---|---|---|---|
| ● | GET, POST `/` | Organizer | Список и создание. Тело: `title`, `type`, `event_date`, `start_time`, `end_time`, `place`, `description`; для предзащиты и защиты блок `evaluation`. Фильтры (необязательные, через «И»; внутри значения через запятую — «ИЛИ»): `type`, `publication_status`, `evaluation_status` (акселераторы при нём не попадают в выдачу), `period=upcoming\|past`, `year=` (год `event_date`, ПР18), `search=`, `ordering=event_date\|-event_date`. Неизвестное значение — `400 invalid_filter` |
| ● | GET, PATCH, DELETE `/{id}/` | Organizer | Карточка и правка; удаление только `draft` |
| ● | POST `/{id}/publish/` | Organizer | `draft → published`; фиксирует `template_id` и `passing_score`, шаблон → `locked`; `event_not_ready` для акселератора без направлений или тренеров |
| ● | GET, POST `/{id}/tracks/` | Organizer | Направления: `role`, `room`, `description`, `capacity` ○ |
| ● | PATCH, DELETE `/tracks/{tid}/` | Organizer | Уменьшение `capacity` ниже числа записанных разрешено; удаление направления с записями запрещено: `409 track_has_enrollments` (ПР9) |
| ● | POST `/tracks/{tid}/trainers/`; PATCH, DELETE `/trainers/{id}/` | Organizer | `user_id`, `position`, `company` |
| ● | GET `/users/?search=` | Organizer | Поиск пользователей по ФИО и логину |
| ● | GET `/announcements/`, `/announcements/{id}/` | Authenticated | Опубликованные мероприятия всех типов с датой не в прошлом, по возрастанию даты. У акселератора: направления, тренеры, остаток мест, объект `enrollment` (`state`, `track_id`). У предзащиты и защиты записи нет; члену команды после публикации расписания — блок `my_schedule` (его добавляет расписание через `AnnouncementEnricher`) |
| ● | GET `/my/trainings/` | Trainer | Акселераторы, где пользователь тренер: направление, аудитория, время, `can_upload` (мероприятие закончилось), материалы |
| ● | POST `/tracks/{tid}/materials/` | Тренер направления | multipart `file`, `title`; `event_not_finished`, `unsupported_file_type`, `file_too_large`, `not_trainer` |
| ● | DELETE `/materials/{id}/` | Загрузивший тренер, Organizer | |
| ● | GET `/{id}/materials/` | Записавшийся студент, тренер, Organizer | Студент получает только своё направление; не записанному — `not_registered` |
| ● | GET `/materials/{id}/download/` | Те же | Ссылка с коротким сроком жизни; права проверяются при каждом запросе |
| ○ | POST `/{id}/registration/open/`, `/close/` | Organizer | `registration_status`; открыть можно только у опубликованного акселератора. Дата автоматического открытия задаётся полем `registration_opens_at` в карточке |
| ○ | GET `/tracks/{tid}/enrollments/` | Organizer; Trainer своего направления (ПР8) | Записавшиеся: ФИО, группа, дата; тренеру только ФИО и группа |
| ○ | POST `/{id}/enrollment/` | Student | `{track_id}`; `capacity_exceeded`, `already_enrolled`, `registration_closed` |
| ○ | PUT `/{id}/enrollment/` | Student | Смена `{track_id}`, атомарно |
| ○ | DELETE `/{id}/enrollment/` | Student | Отмена |

Создание защиты — тоже `POST /api/events/`:

```json
{"title": "Защита, весна 2027", "type": "defense", "event_date": "2027-01-20", "start_time": "10:00", "end_time": "17:00", "place": "Корпус 10",
 "description": "Защита проектов осеннего цикла",
 "evaluation": {"template_id": 7, "source_event_id": 3, "team_ids": [101, 87]}}
```

`team_ids` — подтверждённый организатором список (по умолчанию фронт передаёт все `passed: true`). Сервер в одной транзакции создаёт `events`, `event_evaluations` и `event_teams` без аудиторий и позиций. Ошибки: `invalid_source`, `source_not_closed`, `source_already_used`.

## 5. Пограничные случаи

**Запись на акселератор**

| Случай | Требование |
|---|---|
| Двое записываются на последнее место | Проверка лимита и вставка в одной транзакции: `SELECT … FROM accelerator_tracks WHERE id = ? FOR UPDATE`, подсчёт `track_enrollments`, insert. Проигравший получает `409 capacity_exceeded`; остаток мест в диалоге обновить из ответа |
| Двойной клик | Unique (`event_id`, `user_id`); повтор в то же направление — `200` |
| Смена, а новое направление заполнено | Транзакция: блокировка нового направления, проверка мест, удаление старой записи, вставка новой; при нехватке мест — откат, студент остаётся в старом |
| Лимит уменьшили ниже числа записанных | Записи сохраняются, новые запрещены; организатору «Лимит меньше числа записавшихся: записи сохранены, новых не будет.» |
| Запись закрыли, пока открыт диалог | `409 registration_closed` |
| Отмена или смена после закрытия записи | Запрещены: `registration_closed` (ПР10) |
| Студент отменил запись | Доступ к материалам пропадает |

**Оценки**

| Случай | Требование |
|---|---|
| Эксперт отправляет, а приём уже завершён | `409 event_closed`; на телефоне плашка «Приём оценок закрыт», введённые баллы не теряются до ухода с экрана |
| Плохая связь на телефоне | Черновик хранится локально, отправка с повтором; PUT идемпотентен |
| Двое экспертов ставят «Не явилась» одновременно | Идемпотентно |
| Команде с оценками ставят «Не явилась» | Нужен `confirm: true`; оценки остаются; снятие отметки возвращает итог |
| Эксперта удалили из аудитории после оценки | Оценка остаётся и учитывается; удаление такого эксперта требует `confirm: true` (ПР11) |

**Публикация и защита**

| Случай | Требование |
|---|---|
| Шаблон редактируют после публикации | `template_locked`; правка создаёт копию в `draft` |
| Две защиты из одной предзащиты одновременно | Уникальный `source_event_id`; второй получает `source_already_used` |
| «Вернуть в работу» после создания защиты | `source_locked` |

**Материалы**

| Случай | Требование |
|---|---|
| Загрузка до окончания | `event_not_finished`; окончание = `event_date + end_time` в Asia/Tomsk (ПР13) |
| Файл > 50 МБ или не PDF/PPTX | Проверка на фронте до загрузки и на бэке по сигнатуре файла |
| Прямая ссылка на файл | Подписанные ссылки с коротким сроком; права проверяются при выдаче |
